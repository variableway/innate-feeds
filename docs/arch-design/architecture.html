Architecture Overview · 2026-11-01

innate-feeds 总体框架与模块交互

一个 GitHub 趋势聚合站，采用双部署模式与双域插件结构。 后端 backend/ 负责采集与 API，前端拆成两个域包 @innate/domain-feeds（frontend/）与 @innate/domain-dsh（dsh/），由宿主 frontend/src/main.tsx 组合； 跨层常量与契约收敛在 shared/。

每个方框是该层的真实目录；括号内为该层职责的一句话概括。层与层之间只允许向下依赖。

三、两种部署模式

同一套前端代码，两条数据链路。切换只由 VITE_STATIC_MODE 一个环境变量决定。

API 模式

本地开发 / 自托管后端，SQLite 为准

  • bun run dev → 后端 :4000 + 前端 :3000
  • 前端 /api/* → Hono → SQLite 查询
  • 支持 FTS5 + bm25 相关度排序
  • POST /api/feeds/sync 触发实时采集
  • README 走磁盘缓存 + 后台刷新

静态模式（GitHub Pages）

无后端，预导出 JSON 由 Pages 托管

  • CI 采集 → export-incremental → public/data
  • 前端 /data/*.json 直接 fetch
  • 分片按 snapshot_date 组织，懒加载
  • Digest 合并 GitHub 实时 issue 拉取
  • README 浏览器直连 GitHub，失败回落 /data/readmes

四、域插件契约

两个域包实现同一套接口，由宿主组合；域只声明路由与能力，不携带宿主 UI。

createWebDomain("feeds")

声明域标识。硬条件：包名 @innate/domain-* + 模块导出 webDomain。

.addRoute("app", …)

挂载路由树。每个域自带布局组件与子路由；/dsh 前缀天然完成命名空间隔离。

.addCapability("navItems", …)

向上游声明侧栏条目（label / path / icon / order / group）。宿主据此渲染，域不依赖宿主题库。

.addCapability("homeTile", …)

声明首页磁贴（title / description / path）。

.build()

产出域对象，由 frontend/src/main.tsx 汇入 collectWebDomainRoutes(domains, …) 生成最终 router。

六、一次数据更新走过的路

  1. 触发Actions cron 08:00 UTC / 本地 data:update

    push、schedule、workflow_dispatch 三种入口都落到 backend/src/app/cli.ts 的 sync 分支。

  2. 采集collector/

    每个 collector 实现 fetchLatest()，经 shared/http.ts 带重试拉取；vc-portfolio.ts 逐源编排，单源失败不中断其余。

  3. 落库 / 落文件db/index.ts · data/*-store.ts

    仓库类数据进 SQLite（事务 + 复合主键去重）；外部源进 ~/.innate/<source>/ 的 JSON + manifest。

  4. 导出data/export-incremental.ts

    按日期分片写 frontend/public/data/chunks/，同时导出 digest、plugins、topics、trendshift、external。

  5. 提交workflow_dispatch / schedule 时

    CI 提交数据 chunk 到 main —— 注意这是数据文件，与本仓「不提交数据文件」的手工约定不同。

  6. 构建与部署frontend/scripts/build.ts

    Tailwind v4 编译 → Bun.build 打包 → 注入 VITE_BASE_PATH → 写 404.html + .nojekyll → upload-pages-artifact → deploy-pages。

  7. 消费services/ → pages/

    前端按 isStaticMode() 选择 /api/* 或 /data/*；页面渲染列表，筛选状态存 localStorage。
